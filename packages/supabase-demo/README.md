# @karibu/supabase-demo — demo EHR backend

Sandboxed, PHI-free KaribuEHR backend for recording training/investor videos and
live demos. Full plan: **`docs/demo-environment-plan.md`**.

This package holds everything the demo Supabase project needs that production
doesn't: the consolidated schema **baseline**, PHI-free **seeds**, and a guarded
**reset**. It deliberately does NOT duplicate the ongoing migration chain —
after provisioning, new migrations continue to live in
`packages/supabase/migrations/` and are applied to prod and demo alike.

## Layout

```
migrations/0001_baseline.sql   Consolidated schema (generated — dump of prod; not committed until built)
seed/00_storage_buckets.sql    Buckets + storage policies (mirrors migrations 003/036)
seed/10_reference_data.sql     Global catalogs (GENERATED from prod migrations — no DB access, no PHI)
seed/20_demo_census.sql        The demo cast (GENERATED by scripts/demo-seed/generate-census.ts)
seed/30_clinic_backfill.sql    Per-clinic materializations (GENERATED; runs after the census)
scripts/build-baseline.sh      Dump prod schema -> migrations/0001_baseline.sql
scripts/build-reference-seed.sh  Regenerate seed/10 + seed/30 from ../supabase/migrations
scripts/db-run.ts              baseline | seed | reset (hard-guarded to the demo project)
demo-project-ref               Pinned demo project ref (guard for every db command)
.env                           DEMO_DB_URL (gitignored — never commit)
```

## One-time provisioning

1. **Create the demo Supabase project** (dashboard). Record its ref in
   `demo-project-ref` (replaces the placeholder).
2. **Build the baseline** (schema-only dump of production — needs Docker running
   *or* `brew install libpq && brew link --force libpq` for `pg_dump`):
   ```sh
   PROD_DB_URL='postgresql://…' pnpm --filter @karibu/supabase-demo build-baseline
   ```
   Review `migrations/0001_baseline.sql`, then commit it.
3. **Configure the connection**: put the demo project's Session-pooler URL in
   `packages/supabase-demo/.env` as `DEMO_DB_URL=…`.
4. **Apply baseline + seeds**:
   ```sh
   pnpm demo:baseline   # applies 0001_baseline.sql + marks migrations 001–105 applied
   pnpm demo:seed       # applies seed/*.sql in order
   ```
5. **Clerk**: create a development instance; add one account per role (records,
   nursing assistant, nurse, clinical officer, lab tech, dispenser, admin,
   superadmin) with fictional names. Staff rows auto-create on first login.
6. **Edge functions**: from `packages/supabase`, deploy to the demo ref with
   demo secrets (`CLERK_ISSUER=https://<demo-slug>.clerk.accounts.dev`, demo
   `OPENAI_API_KEY`, demo `INNGEST_EVENT_KEY`):
   ```sh
   supabase functions deploy --project-ref $(cat ../supabase-demo/demo-project-ref)
   ```
7. **Client**: Vercel project **`karibu-demo`** (created 2026-07-14: root
   `apps/web`, Next.js, domain `demo.karibu.health` attached — DNS lives at
   Namecheap; see plan §2.3). Set demo env vars, connect the git repo, deploy.
   The demo is **web-only** (investors on desktop / mobile Safari) — no
   Android demo build.
8. **Nightly reset**: add the `DEMO_DB_URL` repository secret on GitHub —
   `.github/workflows/demo-reset.yml` then resets the demo at 00:00
   Africa/Kampala (skips quietly while the secret is unset; also supports
   manual dispatch before a presentation).

## Ongoing: keeping demo in step with production

New migrations are authored in `packages/supabase/migrations/` exactly as
today. Apply to demo whenever you apply to prod (or batch before a recording
session):

```sh
cd packages/supabase
supabase db push --db-url "$DEMO_DB_URL"
```

`demo:baseline` pre-marked versions 001–105 as applied in the demo migration
history, so `db push` only ever applies migrations newer than the baseline.
Nothing is duplicated into this package.

## Reset between takes

```sh
pnpm demo:reset
```

Truncates all clinical/operational tables (keeps clinics, staff, catalogs,
settings, corpus), clears recorded audio objects, re-applies the seeds, and
unlocks required onboarding for all staff (so guest accounts created during
the day can register patients). Seed dates are `NOW()`-relative, so the OPD
board is always "today". Guests keep their logins across resets; everything
they entered is wiped.

**Guards:** every db command refuses to run unless `DEMO_DB_URL` contains the
ref pinned in `demo-project-ref`, and refuses outright if it contains the
production ref. There is no flag to override either check.

## Rules

- **No PHI, ever.** Baseline is schema-only; reference data is extracted from
  repo files; census content is generated from KaribuLearn canonical cases.
- **No hand edits** to `seed/10_reference_data.sql` / `seed/30_clinic_backfill.sql`
  (regenerate via `build-reference-seed`) or to the baseline (regenerate via
  `build-baseline`; schema cleanup happens as forward migrations in
  `packages/supabase/migrations/`, applied to both environments).
- **Old demo seed migrations** (`004`, `012`, `014` in packages/supabase) are
  superseded by this package for demo purposes; they remain in the prod chain
  as history.

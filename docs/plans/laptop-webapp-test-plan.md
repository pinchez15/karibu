## UX acceptance criteria (pilot sign-off)

These are product gates, not optional nice-to-haves:

1. **Quick path:** dispenser completes Quick mark from the list row without opening the
   detail pane.
2. **Two-pane at laptop width:** full Dispense + stock flow works at 1366×768 with no
   horizontal page scroll.
3. **Auto-advance:** after successful dispense, the next queue row is selected within 500ms
   of queue refresh.
4. **No blank detail:** fetch error shows banner + Retry; never an empty detail pane.
5. **Collapse:** viewport width 1023px → list + sheet; 1024px+ → side-by-side panes.

## Shared constants

Import from the same module as the primitive (do not duplicate magic numbers in tests):

```ts
// apps/web/src/components/master-detail.tsx
export const STATION_COLLAPSE_BP = 1024
```

Vitest and Playwright must import `STATION_COLLAPSE_BP` from this module.

## Key Interactions to Verify

- Dispenser opens the station workspace and sees the full queue as a landscape table
  (target volume ~40-50 patients/day).
- **Hybrid actions:** Quick mark / Partial / Out work inline in the list row without
  selecting the detail pane.
- Selecting a queue row loads the detail pane **side by side** with the list (not a covering
  overlay at ≥ `STATION_COLLAPSE_BP`), full laptop width.
- Dispense + stock dialog opens from list or detail without losing two-pane context at
  laptop width (dialog overlay is OK; full-page navigation is not).
- Resize the two panes via drag handle; split persists for the session (or fixed default
  40/60 if sessionStorage deferred).
- At viewport width `< STATION_COLLAPSE_BP`: two-pane collapses to list + detail `Sheet`.
- Keyboard: ↑/↓ change selection; Enter focuses detail; Escape returns focus to list row.
- PostHog: `station_workspace_viewed` on mount; `station_row_selected` on row select;
  `station_quick_dispense` on inline quick mark.

## Edge Cases

- Detail pane states: empty (nothing selected / hint copy), loading (skeleton), error
  (banner + Retry).
- Queue with zero items (warm empty — existing copy); queue with 50+ rows (list scroll,
  sticky header).
- Narrow viewport (1023px): sheet detail; wide (1024px): side-by-side.
- Revalidation preserves selection by row id when row still in queue.
- Dispense completes → row removed → auto-select next row.
- Partial dispense: row remains; status pill + detail partial copy.
- Concurrent: open Dispense + stock dialog while another row selected — dialog scoped to
  triggering row only.

## Critical Paths

1. **Quick mark (throughput path):** open station → Quick mark on first row → row leaves
   queue or status updates → next row auto-selected. No detail pane interaction.
2. **Full dispense:** open station → select row → Dispense + stock in detail → complete →
   queue updates → next row auto-selected.
3. No auth change this PR — no auth-path critical regression to test now.

## Test types

### Vitest — `MasterDetail` primitive

File: `apps/web/src/components/master-detail.test.tsx` (or colocated).

| Case | Assert |
|------|--------|
| Render list + detail slots | Both panes visible at 1280px viewport (jsdom width mock or resize observer stub) |
| Default split | List ~40% / detail ~60% at first render |
| Collapse at breakpoint | At width `STATION_COLLAPSE_BP - 1`, detail slot renders inside Sheet pattern; at `STATION_COLLAPSE_BP`, side-by-side |
| Empty detail | `detailState='empty'` shows "Select a patient from the queue" copy |
| Loading detail | `detailState='loading'` shows skeleton; list remains in document |
| Error detail | `detailState='error'` shows Retry control; calls `onDetailRetry` on click; no blank pane |
| Keyboard | ArrowDown moves `onSelectedIdChange`; Enter / Escape focus behavior (use `@testing-library/user-event`) |
| `initialSelectionId` | Mount with prop selects matching row |

### Vitest — station page (optional but recommended)

Smoke-test pharmacy page renders `QueueTable` headers and inline quick-action buttons when
queue fixture is non-empty.

### Playwright E2E — pharmacy station

File: `apps/web/e2e/pharmacy-station.spec.ts` (or existing e2e folder convention).

**Setup:** authenticated dispenser session (reuse project auth fixture if present); seed or
mock queue with ≥3 rows.

**Test A — quick mark path**

1. Navigate to `/dashboard/pharmacy`.
2. Assert two-pane layout visible at 1366×768 (list and detail regions both visible OR
   detail shows selected patient — not sheet-only).
3. Click **Quick mark** on first row without clicking into detail pane.
4. Assert row count decreases OR status changes.
5. Assert second row becomes selected (highlight class or aria-selected).

**Test B — full dispense path**

1. Select first row.
2. Open **Dispense + stock** from detail pane (or list).
3. Complete dialog with minimal valid input (match existing dialog fields).
4. Assert queue updates and next row auto-selected.

**Test C — collapse**

1. Set viewport to 1023×768.
2. Select row → detail opens as sheet (not side-by-side second column).
3. Set viewport to 1024×768 → side-by-side restored; selection preserved.

**Test D — error state**

1. Intercept detail fetch (or queue refresh) to return 500 once.
2. Assert error banner visible in detail or list; Retry button present.
3. Assert no empty white detail pane.

### PostHog smoke (staging / manual or mocked)

In staging after deploy, or in E2E with PostHog mock:

- `station_workspace_viewed` fires once on pharmacy page load.
- `station_row_selected` fires on row click with `visit_id` property.

Block release if these two events are missing in staging verification checklist.
